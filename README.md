# odol2mlod

Конвертер 3D-моделей игр Bohemia Interactive: читает бинарный формат **ODOL** (то, что лежит в p3d DayZ и Arma) и пишет редактируемый **MLOD** - тот, что открывают Oxygen 2, Object Builder и Blender-аддон ArmAToolbox. Отдельная программа на C++ без внешних зависимостей, плюс окно на Qt6.

## Зачем

Бинарные ODOL-модели нельзя править - только пересобирать через бинаризатор. MLOD - это их распакованная форма: геометрия, материалы, named selection и память-точки читаются как есть и правятся в любом подходящем редакторе. Обратная операция (MLOD обратно в ODOL) делается штатным бинаризатором Bohemia.

## Консольная версия

```
odol2mlod input.p3d              положит input_mlod.p3d рядом с входом
odol2mlod input.p3d out.p3d      результат по своему пути
odol2mlod input.p3d -v           трассировка чтения по секциям
```

Сборка (любой modern C++-компилятор, нужен C++20):

```
g++ -O2 -std=c++20 -static -Wall -Wextra -o odol2mlod.exe odol2mlod.cpp
```

## GUI (Qt6)

Окно в папке `gui`: файл выбирается кнопкой или перетаскиванием, кнопка "Конвертировать" запускает конвертер, его вывод идёт в лог, готовый файл открывается кнопкой "Открыть папку результата". Путь к p3d можно передать аргументом командной строки - окно откроется и сразу всё сконвертирует.

```
cmake -S gui -B gui/build -G Ninja -DCMAKE_PREFIX_PATH=<путь к Qt6>
cmake --build gui/build
```

Конвертер при сборке кладётся рядом с окном автоматически. Для чужой машины рядом нужны Qt-библиотеки, раскладываются штатным `windeployqt odol2mlod-gui.exe`.

## Что читается

Поддерживаются ODOL v28..v73, проверено на v53 (Arma-моды) и v56 (свежая ваниль DayZ 1.30 и модовые модели). Оба схема сжатия (LZO и LZSS), все LOD - вместе со служебными (геометрия, память, хитпоинты, обзоры), скелет, анимации, proxy, named selection, встроенные rvmat-материалы. MLOD пишется в формате v257 (P3DM), который открывают штатные инструменты.

Формат v56 заметно отличается от описанного в открытых исходниках: свой блок 9 байт перед скелетом в modelInfo, лишний байт в хвосте modelInfo, без animPeriod/initPhase в классах анимаций, без пятого float у Hide, все записи stage и texgen в материале с нулевой плюс одна stageTI в хвосте вместо двух и 52 байт, вложенные массивы в skeletonToSub. Всё выловлено на реальных файлах и подогнано по выравниванию.

## Проверки

Регресс на v53: модель конвертируется байт в байт одинаково с эталонным конвертером DeODOL55UNI - сверяются точки с флагами, нормали, грани, uv и тэги.

Масштаб: 59 p3d подряд (вся папка structures_ruins из ванили, весь Alcohol_Brewery, wr_atv) без единой ошибки, из них жирные модели вроде Ruin_Church на 811 КБ с 11 LOD. Результаты импортируются в Blender через ArmAToolbox, числа вершин и полигонов сходятся с конвертацией до единицы.

## Откуда взят формат

Структура ODOL собрана по открытым проектам: [DeODOL55UNI](https://github.com/spaceldie1/DeODOL55UNI) (декомпилированный DeODOL54, C#) дал каркас чтения для v53 и v54, [odol2mlod от Mikero](https://github.com/Faguss/odol2mlod) (C++) - пример конвейера ODOL в MLOD. Оба конвертера на v56 падают, поэтому ветка v56 доведена самостоятельно hex-разбором файлов.
